## Target file and section

- Новый файл: `software/<kebab-case-name>.yml`. Правило: имя в kebab-case, по названию программы. Для "favicons" это `software/favicons.yml`; файла с таким именем в репозитории пока нет.
- Отдельного README для правки нет: Markdown-список https://github.com/awesome-selfhosted/awesome-selfhosted генерируется из YAML. Раздел определяет первый тег в `tags:`. В одностраничном режиме программа показывается только в первой категории из списка.
- Готового тега для "favicon / icon API" нет. Существующие теги, которые могут подойти (выбор за мейнтейнером, имена берите из `name:` в `tags/*.yml`):
  - `tags/miscellaneous.yml`: в CONTRIBUTING он назван тегом для программ, которые не подходят ни под одну категорию.
  - `tags/software-development---api-management.yml`, `tags/software-development.yml`, `tags/personal-dashboards.yml` (иконки для дашбордов и стартовых страниц), `tags/media-management.yml`.
  - Новый тег создать нельзя: он должен быть хотя бы у 3 программ.
- Платформы, требуемые схемой (`platforms/*.yml`): есть `rust.yml` и `docker.yml`. Правило: указывать то, что нужно для установки и запуска.

## Entry

Не написано намеренно, см. блок вверху. Мейнтейнер пишет его сам по шаблону `.github/ISSUE_TEMPLATE/addition.md`. Что в нём должно быть:

| Поле | Обязательно | Правило |
|---|---|---|
| `name` | да | название программы |
| `website_url` | да | домашняя страница |
| `source_code_url` | да | ссылка на полный исходный код |
| `description` | да | короче 250 символов, sentence case; без "open-source/free/self-hosted"; лучше короткая форма без "A ..." и без "X is ..."; если распространяется одним статическим бинарником, указать язык; `(alternative to X)` в конце, если уместно |
| `licenses` | да | идентификаторы из `licenses.yml` (там есть SPDX-идентификатор `MIT`) |
| `platforms` | да | из `platforms/` |
| `tags` | да | из `tags/`; первый тег определяет раздел |
| `depends_3rdparty` | нет | true, если программа зависит от стороннего сервиса вне контроля пользователя; это стоит честно продумать: сервис по природе ходит на чужие сайты за иконками |
| `demo_url` | нет | только интерактивное демо, не видео |
| `related_software_url` | нет | список клиентов/плагинов (например, README npm-клиентов) |
| `icon_url` | нет | предпочтительный источник: dashboardicons.com |

Перед отправкой удалить комментарии и неиспользуемые необязательные поля. Вставлять заголовки в YAML нельзя.

## Insertion point

Не применимо: каждая программа лежит в своём файле `software/<name>.yml`, а сортировку и раздел в Markdown задаёт генератор. Изменение — один новый файл:

```diff
+ software/favicons.yml   (новый файл, содержимое пишет мейнтейнер)
```

## PR title

Сообщение коммита по CONTRIBUTING: образец `add My Awesome software`. Если выбрать путь через issue, шаблон addition.md задаёт заголовок `Add SOFTWARE_NAME`. Сформулировать его — дело мейнтейнера.

## PR body

Тело не "(empty)": шаблон PR требует оставить текст и отметить чекбоксы. Это перекрывает правило "описание PR оставлять пустым". Заполнить и отметить чекбоксы мейнтейнер должен **сам**. Агент не может отметить пункт про "human, not a machine/LLM" или написать его эквивалент. Шаблон: `.github/PULL_REQUEST_TEMPLATE.md`.
